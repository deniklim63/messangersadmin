# Админка ботов

Общая база пользователей Telegram- и ВК-ботов: кто откуда пришёл, какие данные оставил,
из какого города. Один человек — одна карточка, даже если он написал в несколько ботов.

## Что умеет

- **Подключение ботов.** Telegram — webhook прописывается кнопкой из карточки бота.
  ВКонтакте — достаточно ключа доступа сообщества: Callback API настраивается сам
  (адрес, подтверждение, секрет, нужные события).
- **Сбор данных.** По умолчанию бот только собирает то, что человек прислал сам
  (телефон и e-mail вытаскиваются из текста). Встроенная анкета (имя, телефон,
  e-mail, город) включается в настройках бота — чтобы не мешать чужой логике.
- **Склейка людей.** Если телефон или e-mail совпал, записи из разных ботов
  объединяются в один контакт — видно, что человек есть и в TG, и в ВК.
- **Фильтры и выгрузка.** По городу, по боту, «есть в 2+ ботах», поиск; CSV-экспорт
  и CSV-импорт (например, из salebot).
- **Входящие.** Чат с пользователем как в ManyChat: непрочитанные, звук, мгновенная
  доставка через SSE, форматирование, картинки/видео/файлы в обе стороны,
  передача диалога оператору и возврат боту.
- **Рассылки.** Выбор бота, сегментация по городам, оформление текста
  (жирный, курсив, подчёркнутый, ссылка), картинка или видео, история отправок.
- **Сценарии.** Визуальный конструктор диалога: сообщения с кнопками и картинками,
  GET/POST-запросы, свой JS-код, условия, паузы, вопросы с проверкой
  (телефон, e-mail, дата, город по справочнику и OpenStreetMap), передача оператору.
  Переменные `{{name}}`, `{{city}}`, списки из ответа API, даты
  (`{{today}}`, `{{weekEnd}}`…). Сценарий привязан к боту, один активный на бота.
- **Аналитика.** Графики по каждому боту: пользователи, подписки, отписки, фильтр по дате.

## Запуск

```bash
npm install
npm run db:up        # Postgres в Docker, порт 5433
npm run db:migrate   # применить схему
npm run dev          # http://localhost:3100
```

Пароль входа — `ADMIN_PASSWORD` из `.env` (по умолчанию `admin`).
База стартует пустой: добавьте первого бота в разделе «Боты».
Полезные команды: `npm run db:studio` — Prisma Studio, `npm run db:reset` — пересоздать базу с нуля.

## Настройки (.env)

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | подключение к Postgres |
| `ADMIN_PASSWORD` | пароль входа в админку |
| `AUTH_SECRET` | подпись сессионной cookie, в проде: `openssl rand -hex 32` |
| `APP_URL` | публичный адрес — из него строится webhook-URL для ботов |
| `POSTGRES_PASSWORD` | только для прода (`docker-compose.prod.yml`) |

## Как подключить Telegram-бота

1. Возьмите токен у [@BotFather](https://t.me/BotFather).
2. **Боты → Новый бот**, платформа Telegram, вставьте токен. Токен сразу проверяется
   через `getMe` — если он неверный, бот не создастся.
3. Нужен публичный **https**-адрес (Telegram не принимает http) — на проде он уже задан.
   Локально webhook подключить нельзя: поднимите `ngrok http 3100` и пропишите адрес
   в `APP_URL`, либо просто подключайте бота на проде.
4. В карточке бота нажмите **Подключить webhook**. Строка статуса покажет, что Telegram
   принял адрес; ниже, в «Последних событиях», видно каждый входящий запрос.

## Как подключить сообщество ВКонтакте

1. Управление сообществом → Работа с API → Ключи доступа: создайте ключ с правами
   на сообщения и управление сообществом.
2. **Боты → Новый бот**, платформа ВКонтакте, вставьте ключ — остальное админка
   настроит сама через API (Callback-сервер, подтверждение, события).

## Внешние источники данных

Если бот написан отдельно (aiogram, grammY, форма на сайте), данные можно слать напрямую.
Токен — в карточке бота.

```bash
curl -X POST https://<APP_URL>/api/ingest \
  -H "Authorization: Bearer <ingestToken>" \
  -H "Content-Type: application/json" \
  -d '{"externalId":"123","name":"Иван","phone":"+79991234567","email":"i@mail.ru","city":"Казань"}'
```

Обязателен только `externalId` — идентификатор человека в этом источнике.
Телефон нормализуется (`8 999…` и `+7 999…` — один и тот же номер), город приводится к
единому написанию, поэтому «Ёкатеринбург» и «екатеринбург» не расползутся на две записи.

## Устройство

| Что | Где |
| --- | --- |
| Схема БД | `prisma/schema.prisma`, миграции в `prisma/migrations` |
| Клиент Prisma | `src/lib/db.ts` (ленивый, driver adapter `@prisma/adapter-pg`) |
| Авторизация | `src/lib/auth.ts` — один пароль, HMAC-cookie |
| Склейка контактов, нормализация | `src/lib/contacts.ts`, `src/lib/extract.ts`, `src/lib/cities.ts` |
| Анкета (если включена) | `src/lib/survey.ts` |
| Движок сценариев | `src/lib/scenario.ts`, переходы — `src/lib/scenario-routing.ts`, шаблоны — `src/lib/scenario-template.ts` |
| Конструктор сценариев | `src/components/scenario-canvas.tsx`, `block-editor.tsx`, геометрия — `src/lib/scenario-layout.ts` |
| Вызовы Telegram и ВК | `src/lib/platforms.ts`, вложения — `src/lib/attachments.ts` |
| Приём вебхуков | `src/app/api/webhooks/*` |
| Внешний приём данных | `src/app/api/ingest/route.ts` |
| Live-события входящих | `src/app/api/inbox/events` (SSE) + `src/lib/events.ts` |
| Отложенные шаги сценария | `src/lib/scheduler.ts`, стартует из `src/instrumentation.ts` |
| Server actions | `src/lib/actions-*.ts` |
| Страницы админки | `src/app/(admin)/*` |

Особенности, о которых стоит знать:

- Next.js 16 / React 19 / Prisma 7 — перед правками см. `AGENTS.md`
  и `node_modules/next/dist/docs/`.
- Файлы с `"use server"` могут экспортировать только async-функции — `deploy.sh`
  это проверяет перед заливкой.
- Проверка типов вынесена из `next build` (`ignoreBuildErrors`): VPS на 1 vCPU
  падал от `tsc`. `deploy.sh` запускает `tsc --noEmit` и `eslint` локально.
- Медиа хранятся в Postgres (`MediaFile`), отдаются через `/api/files/[id]`
  (только авторизованным) и `/api/media/[id]` (картинки сценариев, публично).
